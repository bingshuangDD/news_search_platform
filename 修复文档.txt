在 SQLAlchemy 2.0 的异步模式下， await db.execute(stmt)

实际上  rowcount  是存在的，但 Pylance 的类型推断认为它不存在。
因此对原先的学习代码进行修改，用更符合sqlalchemy 2.0 的语法来进行编写

二.对于推荐新闻的获取问题
如果我想返回的时候只带一些东西（例如：id，title），而不是返回所有的字段）
两种方法筛选：
一种是列表推导式（先scalars.all后再[{}]筛选）-->也就是代码中的方案
一种是带参数的select
例如：stmt = (
        select(
            news.News.id,
            news.News.title,
            news.News.views
        )
        .where(...)  
        .order_by(...)
        .limit(10)
    )
运行效率上后者会高，但是执行方案以及对短limit 的查询上差距不大，所以就维持原样

二.关于哈希密码的问题
我们报了这个错： File "D:\Fastapi+Vue-新闻头条项目\backend\app\utils\security.py", line 7, in get_hash_password
    return pwd_context.hash(password)
为什么？因为bcrypt 限制密码长度不能超过 72 字节。
我有两个地方没搞懂。第一，我在swagger文档里面只是try了"username": "nagger",
  "password": "123456"，怎么看都没超限，为什么会到bcrypt的阈值？
第二，哈希加密应该不会将短字节的字符串膨胀到60以上？
原因是bcrypt 5.0.0 与 passlib 1.7.4 不兼容。
你的密码 "123456" 完全没问题。真正出问题的是 passlib 内部的 detect_wrap_bug 函数——它在初始化 bcrypt 后端时用了一个恰好 72 字节的测试值，而 bcrypt 5.x 对这个测试值直接抛出了 ValueError。
因此我们不用passlib，而单独用bcrypt
